# How GK2 Donkey API answers a game update that changed the code of a game member it uses, by the mod's own class
# that uses the member (GameCode.cs reads this at start; docs/dependency-check.md). tests/CecilScan-DonkeyAPI fails
# when a class of the built DLL that uses game members is listed nowhere here, so every new class gets sorted.
#
#   core <classes>               the mod stops (Safety.ForceRunOnChangedGameCode runs it anyway, the chest off)
#   frozen <feature>: <classes>  that feature is off for the session (its patches are not applied), the rest runs
#   warned <feature>: <classes>  that feature runs on the changed code; the warning names it
#   dev <classes>                the dev tools are locked for the session; the mod runs
#   verify <classes>             the start-up verifier: not a user of the member (Access.Verify names what others use)
# A member used by classes of several kinds takes the most serious one. A class listed nowhere counts as core.
